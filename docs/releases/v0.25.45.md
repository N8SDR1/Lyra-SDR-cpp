# Lyra v0.25.45 — Jugum · mouse wheel after a drop-down

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name **Jugum** (δ Lyrae), next
after Alathfar. Patch over v0.25.44. Build date **2026-11-19**.

Installer app identity stays **Lyra-cpp** (same QSettings as Alathfar).
Install over 0.25.44; settings stay.

**Scope:** mouse wheel after a drop-down, and Mode list close. Several
operators found the wheel (VFO, spectrum / waterfall) stopped after
picking from a Lyra list until they clicked another program and came
back. Once, the **Mode** drop-down went dead to clicks and the wheel
until Alt-Tab. How the wheel tunes and zooms is unchanged. **QRV**,
**WDSP 2.11**, and **ASIO for VAC (test)** are unchanged.

## Summary

- **Wheel after a drop-down.** When a list closes without giving focus
  back, Lyra returns focus to the main window — only while Lyra is the
  program in use. A list left “open” off screen closes the next time the
  wheel rolls over its drop-down.
- **Mode switches just after its list closes** (VFO A and VFO B).
- **Test switch:** Settings → Visuals → **Draw drop-down lists inside
  the panel** (off by default).
- **Log lines** for reports: `[ui] a drop-down list closed without
  returning focus` and `[ui] drop-down list was open under the wheel —
  closed`.
- **Unchanged:** QRV double-click tune (0.25.44). QRV board opt-in
  (0.25.43). WDSP 2.11 + CW NNR models (0.25.42). ASIO for VAC in test
  (0.25.41).

## What testers should try

Wheel tuning, spectrum / waterfall wheel, and the drop-downs should
still work as they did. Operators who saw the stall: pick from a
drop-down, then roll the wheel. If it still stalls: (1) Help → Show
Log… → Save; (2) Windows Settings → Bluetooth & devices → Mouse →
**Scroll inactive windows when I hover over them**; (3) Settings →
Visuals → **Draw drop-down lists inside the panel**. Say which of those
helped.
