# Lyra v0.25.37 — Sheliak · 7000DLE / 8000DLE transmit

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.36. Build date **2026-11-05**.

**Scope:** ship Protocol 2 transmit on the **Orion MkII** board class so
an **ANAN-7000DLE**, **ANAN-8000DLE**, **Orion MkII**, or **Anvelina-Pro3**
keys like Brick3SDR / ANAN-100D (Enable PA + MOX + Drive). Those radios
no longer need **Settings → TX → Arm Protocol 2 TX**. **G2 / G2-1K**
still use the dummy-load arm. Red Pitaya still has no Protocol 2 TX
profile. Protocol 1 ANAN is still refused. No receive DSP change.

## Summary

- **7000DLE / 8000DLE / Orion MkII / Anvelina-Pro3 transmit.** Same P2
  DUC / Enable-PA path as ANAN-100D. Pick the marketed model in
  Settings → Hardware, run **Protocol 2**, tick **Enable PA**, set
  Drive above 0. First RF on a new box: dummy load. You do **not**
  tick Arm Protocol 2 TX for these models.
- **Unchanged:** G2 / G2-1K still need the dummy-load arm. Red Pitaya
  has no P2 TX profile. A Brick or classic ANAN still on Protocol 1 is
  refused on Open (flash P2). HL2 / Brick / 10 / 100-series TX posture
  is unchanged.
- **Docs note (same tag):** FAQ + limitations now say Lyra is **not**
  Thetis-CMASIO — a Behringer WING / X32 over ASIO will not map the
  way it does there. Ordinary Windows audio (WASAPI) still works.

## Detail — Orion MkII TX (`e17f42a`)

The Orion MkII Protocol 2 profile (`kOrionMkiiProfile`) covers
**ANAN-7000DLE**, **ANAN-8000DLE**, **Orion MkII**, and **Anvelina-Pro3**.
It already had the two-BPF Alex words, DDC2/DDC3 RX map, and Alex1
enable. Transmit stayed behind the bench interlock (`txOnAirValidated`
false), so MOX did nothing useful until **Arm Protocol 2 TX**. That
flag is now true: the radio auto-arms on a healthy connect, the
per-P2 drive ceiling is not applied, and TX keys off **Enable PA +
MOX + Drive**.

Saturn (**G2 / G2-1K**) is a different profile and stays dummy-load
armed.

## Bench — 7000 / 8000 operator

- Settings → Hardware: marketed model (**ANAN-7000DLE** /
  **ANAN-8000DLE** / **Orion MkII** / **Anvelina-Pro3**), **Protocol 2**.
- Settings → TX: **Enable PA** on. Drive low, then walk it up. Dummy
  load on first TX.
- **Arm Protocol 2 TX** is not required for these models (G2 still
  needs it).
- MOX / TUN into the dummy load: RF, PA current, filters follow the
  band (Anvelina PROIII already showed BPF follow).
- Protocol 1 row in Discover: still **refused** — flash P2.
