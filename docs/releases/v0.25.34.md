# Lyra v0.25.34 — Sheliak · HL2 IO board sequencer

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.33. Build date **2026-10-31**.

**Scope:** the N2ADR **HL2IOBoard** (Pico, I2C **0x1D**) path on
Protocol 1 only. No other wire or DSP behaviour changes. Protocol 2
(Brick / ANAN) does not use this path and is unchanged; a Brick3
Protocol 2 session including PureSignal TX was checked for zero IO-board
activity.

## Summary

- **IO-board writes are periodic, like deskHPSDR.** Write-on-change I2C
  is gone. Lyra latches one snapshot (TX Hz, RF1 / Alt, RX codes) and
  re-sends registers **0–4, 11, 13, 14** every cycle (~0.35 s). A write
  the Pico misses is repeated next cycle. Band hop → Pico commit ≈ 0.2 s.
- **Board detection.** The PCA9536 ID chip at **0x41** is probed (the
  same probe Thetis / deskHPSDR use); **0x1D** is written only once it
  answers. 10 probes at ~1.7 s, then every ~30 s. No board → no 0x1D
  traffic.
- **New Settings → Filters / BCD → IO board group:** Status
  (Detected / Not detected / Forced present), **Transverter bands
  send** (Hold last HF frequency — default — or On-air RF frequency),
  **Send RX frequency codes (13 / 14)**, **Force IO board present**
  (DIY Pico without PCA9536; deskHPSDR `force_iob`).
- **`LYRA_NO_IOBOARD_FCODE=1`** is retired; the RX-codes checkbox
  replaces it. Delete the variable if you set it.
- **REG 11** is only ever **0** (RF1) or **2** (Alt); never 1. TX
  registers are never written with 0 Hz.
- Verbose **`[iob]`** log records (latch / W / R / reply / slip /
  restart) for bench diagnostics — Settings → Hardware → **Enable
  verbose debug logging** (also in Help → Show Log…), reproduce, then
  send `%APPDATA%\N8SDR\Lyra-cpp\logs\lyra-log.txt`; standalone frame
  harness + ctest.
- **Fixes the reported symptoms:** random / mixed-byte TX Hz on the Pico,
  REG 11 stuck after a 2 m → HF hop, RF1 / Alt not sticking, J4 band
  voltage not following the band.
- **Not in this release:** transverter slot count 4 → 8 and OC Control
  rows for the broadcast (SWL) bands (queued). Per-slot Xvtr OC rows
  have been in Filters / BCD since v0.25.29.

## Detail — the sequencer (`f6eb10f`, `bf04ef4`)

Modelled on deskHPSDR's periodic IO-board model: **11 slots × 12 EP2
datagrams** (~31.5 ms per slot, ~346 ms per cycle).

| Slot | Action |
|---|---|
| 0 | Latch a snapshot: TX Hz, REG 11 (RF1 / Alt), RX fcodes 13 / 14 |
| 1 | Detection probe — read PCA9536 at 0x41 (until present) |
| 2–6 | Write registers 0–4 (TX Hz, five bytes; **register 4 commits**) |
| 7 | Write REG 11 (0 = RF1, 2 = Alt RX) |
| 8–9 | Write registers 13 / 14 (RX1 / RX2 frequency codes) |
| 10 | idle |

Every cycle re-sends from the same snapshot — no queue, no dedupe, no
retry logic. A changed snapshot (band hop, RF1 ↔ Alt, SUB on / off) or a
fresh detection restarts the cycle at slot 0 at the next schedule point
(a running restarted cycle is allowed to finish, so nothing starves).

Each IO write rides in the **second USB frame** of its datagram and
**slips one datagram** when the first USB frame of that datagram, or the
second frame of the previous one, is the gateware's own round-robin
case 0 (OC / RX-ant / dither) or case 10 (mic boost). Those frames can
start a gateware bus-2 transaction of their own, and the HL2 I2C bridge
holds only one command at a time; the slip keeps Lyra's write from being
dropped behind it.

Regs 0–4 are sent only when the snapshot carries a TX value (never
0 Hz). REG 11 is sent every armed cycle and can only encode 0 or 2.

## Detail — detection and Force present (`bf04ef4`, `b0289d1`)

- Present ⇔ the EP6 reply echoes addr 0x3D with RQST and
  `(C4 & 0x0F) == 0x01` from the 0x41 read. Until then nothing is
  written to 0x1D. Probe cadence: 10 × ~1.7 s, then ~30 s.
- **Force IO board present** skips the probe and arms every cycle. For a
  Pico on I2C bus 2 without the PCA9536. Default off; live toggle.
- Status line in Settings → Filters / BCD → IO board: **Detected /
  Not detected / Forced present / Protocol 2 — not used**.

## Detail — Transverter bands send / RX codes (`b0289d1`)

- **Hold last HF frequency** (default): while TX is in an Xvtr slot,
  registers 0–4 keep the last HF TX frequency so an analog band-volts
  amp on J4 (GPA100 / XPA125B class) does not hop. If no HF frequency
  has been used yet, 0–4 are not sent until one has.
- **On-air RF frequency**: send the real RF frequency on every band
  (144.2 MHz → 2 m band volts on J4).
- **Send RX frequency codes (13 / 14)**: default on, as deskHPSDR.
  Replaces `LYRA_NO_IOBOARD_FCODE=1`.

## Bench

N8SDR HL2+ with the N2ADR filter board and **no** IO board: correct
detection-absent behaviour with zero 0x1D traffic. Forced-present wire
capture shows correct bytes, order and timing. Warm restart, power-cycle,
live force toggle and fast band hops clean. Brick3 Protocol 2 session
(including PureSignal TX) shows no IO-board activity. Pico-side
confirmation (J4 band voltage, IO-Control readback) comes from the
testers with boards: Mike K7MDL, Randy W7CPA, Volker DL1VE.

Standalone frame harness `test_hl2_ioboard_frames` and ctest
`hl2_ioboard_publish_paths_static` green.

## If it misbehaves

Reinstall **v0.25.33** from GitHub (write-on-change IO-board path, always
written on Protocol 1). Settings stay. **v0.25.22** remains the long
return point.

## Install

Download **Lyra-Setup-0.25.34.exe**. Windows 10 / 11. Click **▶ Start**,
pick your radio.
