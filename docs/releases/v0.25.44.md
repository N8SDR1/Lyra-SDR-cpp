# Lyra v0.25.44 — Alathfar · QRV double-click tune

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name **Alathfar** (μ Lyrae), next
after Alya. Patch over v0.25.43. Build date **2026-11-17**.

Installer app identity stays **Lyra-cpp** (same QSettings as Alya).
Install over 0.25.43; settings stay.

**Scope:** **QRV double-click to tune** on the floating roster. A Lyra
row that shows Hz tunes the focused VFO. STD / Logger / no-Hz rows do
not. The public list is **https://qrvsdr.cc** (not a tune surface).
**WDSP 2.11** and **ASIO for VAC (test)** are unchanged.

## Summary

- **Double-click a Lyra+Hz row** on View → QRV (or the toolbar QRV chip
  panel). The focused receiver (green border — RX1 or RX2) goes to that
  carrier and the posted Lyra mode, same path as a TCI / cluster /
  panadapter spot.
- **Single-click** only highlights the row.
- **STD, Logger, and rows without Hz** do not retune. Same callsign on
  two apps is two rows; only the Lyra line tunes.
- **Unchanged:** QRV board opt-in (0.25.43). WDSP 2.11 + CW NNR models
  (0.25.42). ASIO for VAC in test (0.25.41).

## How to use

1. Settings → Network → **Enable QRV board**. Share exact frequency if
   you want Hz on the roster (default off).
2. Open **View → QRV** or the toolbar **QRV** chip.
3. **Double-click** a Lyra station that shows Hz.

## What testers should try

Leave QRV off: no change. With QRV on, double-click a Lyra+Hz row and
confirm only the focused VFO moves. Single-click should not retune.
STD / Logger / no-Hz rows should not retune. Report issues with a log
from `%APPDATA%\N8SDR\Lyra-cpp\logs\lyra-log.txt`.
