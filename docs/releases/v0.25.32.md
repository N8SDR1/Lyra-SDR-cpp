# Lyra v0.25.32 — Sheliak · J4 analog-first, P2 PS replica, STD

> **NOT RELEASED.** v0.25.32 was tagged (`9be343a`) and the tag was pushed,
> but no GitHub Release or installer was ever published. The "P2 PS replica"
> host-DUC fallback below turned out to be a PureSignal regression (not a
> valid reference). It was removed and the real root cause fixed in
> **[v0.25.33](v0.25.33.md)**, which also carries the J4 analog-first and STD
> items from this note. Upgrade **v0.25.31 → v0.25.33**.

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This was intended as a **full** GitHub release. Star name stays **Sheliak**.
Patch over v0.25.31. Build date **2026-10-29**.

## What's new since v0.25.31

- **J4 analog-first.** Analog BYTE0–4 goes on I2C2 **before** Pico GPIO
  fcodes 13/14 so leftover PWM cannot pin J4 on the previous band
  (Volker / Mike: 12 m stuck on 20 m). VHF RF above **54 MHz** is not
  packed into J4 (2 m xvtr leftover reading as 80 m).
- **PureSignal tightening (Protocol 2 replica).** When the radio's
  TX-DAC echo is present on the odd DDC0 samples, that replica goes
  into `pscc`. If those samples are empty, the host DUC tap is used
  so collect can start. This is **not** a claim of DeskHPSDR-identical
  PureSignal on Brick2 until D1 moves on B2 / Greg.
- **Suggested Apps: STD.** Settings → **Apps** → Tested with and
  recommended lists **STD** (N8SDR's digital-modes app). Title opens
  <https://github.com/N8SDR1/STD/releases>; details open
  <https://n8sdr1.github.io/STD/>. Connects over TCI, which carries rig
  control and audio. This is **not** Hardware → Startup (that row stays
  SDRLogger+).

## If it misbehaves

Reinstall **v0.25.31** from GitHub. Settings stay. **v0.25.22** remains
the long return point.

## Install

Download **Lyra-Setup-0.25.32.exe**. Windows 10 / 11. Click **▶ Start**,
pick your radio.

**[Lyra-Remote](https://github.com/N8SDR1/Lyra-Remote/releases/latest)**.
