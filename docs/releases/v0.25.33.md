# Lyra v0.25.33 — Sheliak · stability upgrade (recommended for all Protocol 2 radios)

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.31. Build date **2026-10-30**.

> **v0.25.32 was tagged (`9be343a`) but never published as a release.** Its
> installer carried a PureSignal regression (a host-side "replica" fallback
> that was not a valid reference). Everything that was good in 0.25.32 is in
> 0.25.33; the bad part is gone. Treat **v0.25.31 → v0.25.33** as the upgrade.

## Summary

- **Recommended upgrade for all Brick / Protocol 2 operators.** Fixes a TX
  drive handling issue present since **v0.25.16** that affected PureSignal
  calibration below full drive. PureSignal now calibrates at normal
  operating drive levels on Brick2 / Brick3. **Protocol 1 / HL2 unchanged.**
- **Before your first transmit after upgrading: turn Drive down and walk it
  up.** On Protocol 2 radios the same Drive slider setting now produces
  more RF than previous versions (about **+8 dB at 40 %**, **+10 dB at
  30 %**; **TUN included**). Essential if you drive an external amplifier.
  **Re-run TUN on each band.**
- **CTUN on Protocol 2:** the panadapter stays locked at the engagement
  point and audio follows the VFO, matching Protocol 1 behaviour.
- **I/O board (J4 analog PWM)** is now sent **before** band fcodes;
  VHF / transverter frequencies no longer push a wrong analog band.
- **PureSignal at 48 kHz** sample rate on Protocol 2 fixed.
- **Suggested Apps:** **STD** (N8SDR digital-modes app) added —
  <https://github.com/N8SDR1/STD/releases>.
- Internal: removed an experimental PureSignal host-reference path; tests
  added.

## **OPERATOR WARNING — read before the first key-up**

**After this upgrade the same Drive slider position produces MORE RF on
Protocol-2 radios than v0.25.16–0.25.31 did** — roughly **+8 dB (about
6×) at 40 % Drive, +10 dB (about 11×) at 30 %**, and more the lower the
slider sits. TUN power rises the same way. 100 % is unchanged only on a
band whose PA Gain is 100 or higher; a band with PA Gain below 100 is
hotter at 100 % too.

**If you drive an external amplifier — especially a low-drive amp such as
the VK 1 kW — turn Drive DOWN before keying and walk it up while watching
the radio's output.** Do not key first and look second.

Learned amp **watts-cap ceilings are reset once** on the first open of each
P2 rig after upgrading (they were learned under the doubled curve and are
wrong for unity IQ). Re-run **TUN** per band to re-learn the cap. HL2 /
Protocol-1 learned ceilings are untouched.

## Detail — Protocol 2 TX drive / PureSignal (`e95b135`, `a278e9b`, `12cd393`)

**The bug.** v0.25.16 through v0.25.31 (and the unreleased v0.25.32 tag)
scaled the **Protocol-2 TX IQ** with the Drive slider *on top of* the analog
drive byte HP `[345]`. Drive was applied twice. The radio's TX-DAC replica
that PureSignal uses as its reference follows the IQ, so below full drive it
never reached SetPk (0.2899) and the calibrator could not finish collecting:
**FB 0 / cal 0 / st 4**, and the auto-attenuator walked the coupler pad down
to **0 dB** on every band (Greg VK3KV, Brick2). PureSignal on Brick2 /
Brick3 only had a chance at 100 % Drive.

**The fix.**

- **P2 TX IQ stays at unity**; watts live on HP `[345]` only. This is what
  DeskHPSDR (`do_scale = 0` for every radio except Penelope / HL2) and
  Thetis (`SetTXFixedGainRun(0, false)`) do. PureSignal now collects at
  **any** drive on Protocol 2. **HL2 / Protocol 1 power handling is
  unchanged.** (`src/tx/TxDriveSplit.h`, `scratch/test_tx_drive_split.cpp`.)
- **Host DUC tap removed** (the v0.25.32 fallback "replica" from the host
  TX stream, `94e5056`). It ran at the wrong rate with no time alignment
  and was never a valid PureSignal reference. `pscc` is fed from the radio
  pair only (even = coupler, odd = TX-DAC replica), as before v0.25.32.
  The `+3` DDC-config byte write on every DDC slot from v0.25.32 is also
  gone.
- **48 kHz PureSignal fix**: the one-ADC 48 kHz IQ trim (−29 dB) no longer
  applies while PS is live, so a Brick2 operator at 48 kHz gets a
  full-scale coupler / replica into the calibrator.

Deep reference: `docs/PS_P2_REGRESSION_REPORT.md`.

## Detail — CTUN on Protocol 2 (`2ae5848`)

Brick P2 was writing the VFO to DDC0 while WDSP still shifted, so heard RF
disagreed with the LED. DDC0 now stays on the frozen pan centre; TX / DUC
stays on the VFO — the same model Protocol 1 has always used.
(`src/wire/P2TuneHz.h`, `scratch/test_p2_ctune.cpp`.)

## Detail — I/O board J4 analog-first (`54afb17`, carried from 0.25.32)

Analog BYTE0–4 goes on I2C2 **before** Pico GPIO fcodes 13/14 so leftover
PWM cannot pin J4 on the previous band (Volker / Mike: 12 m stuck on 20 m).
VHF RF above **54 MHz** is not packed into J4 (2 m xvtr leftover reading as
80 m).

## Detail — Suggested Apps: STD (carried from 0.25.32)

Settings → **Apps** → Tested with and recommended lists **STD** (N8SDR's
digital-modes app). Title opens <https://github.com/N8SDR1/STD/releases>;
details open <https://n8sdr1.github.io/STD/>. Pair over TCI / VAC. This is
**not** Hardware → Startup (that row stays SDRLogger+).

## Notes

- `SetPSDeadlockMinFrac` is not exported by the bundled `wdsp.dll` (TAPR
  2.10); the guarded call in the PS arm path is inert and the effective
  value is the compiled-in 0.06. Left as-is.
- Auto-attenuator math, thresholds, three-tick sequence and per-band pad
  persistence are unchanged.

## If it misbehaves

Reinstall **v0.25.31** from GitHub (PureSignal on P2 will again only work at
full drive there). Settings stay. **v0.25.22** remains the long return point.

## Install

Download **Lyra-Setup-0.25.33.exe**. Windows 10 / 11. Click **▶ Start**,
pick your radio.

The browser desk is a second download:
**[Lyra-Remote](https://github.com/N8SDR1/Lyra-Remote/releases/latest)**.
