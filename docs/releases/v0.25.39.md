# Lyra v0.25.39 — Sheliak · HiDPI display, ANAN model, log on-screen

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.38. Build date **2026-11-08**.

**Scope:** the spectrum and waterfall stay sharp on high-DPI screens
(4K at 150 % Windows scale). A Protocol 2 ANAN whose saved record had
a blank model now gets its filter-board profile. The Log window keeps
its button row on screen. **DeepFist** pitch lock is already in
v0.25.38. No Protocol 2 / HL2 wire change.

## Summary

- **HiDPI display.** The spectrum trace and peak-hold line are a
  triangle ribbon one **logical** pixel thick. GPU lines always draw
  one **screen** pixel wide, so at 150 % / 4K the trace used to look
  thinner and fainter than on 1080p. Waterfall history grows from 512
  rows to the pane's on-screen height (capped at 1024), so a tall pane
  is no longer a 512-row image stretched into a soft blur.
- **ANAN blank model → filter profile.** A Protocol 2 ANAN with no
  saved model now fills one from the reported board (Orion →
  ANAN-200D) or from Settings, so BPF/LPF relays follow Lyra instead
  of the last program. Brick and any radio that already has a model
  are untouched.
- **Log window stays on screen.** **Help → Show Log…** shrinks and
  moves so **Copy all** / **Save** / **Open log folder** sit inside
  the visible area (inside the taskbar) at 4K @ 150 %. A window that
  already fits is left alone.
- **Unchanged:** DeepFist pitch lock (0.25.38). 7000DLE / 8000DLE /
  Orion MkII / Anvelina-Pro3 TX, Xvtr BYTE0–4, Metis STOP. G2 dummy-
  load arm. Protocol 1 ANAN refused.

## Display / 4K

Use **Windows Display scale** (Settings → System → Display). Do
**not** set `QT_SCALE_FACTOR`. **Auto-fit the waterfall dB range**
(Settings → Visuals / Display) is the colour-map control — it does
not replace Windows scale, and it is not a DPI substitute.
