# Lyra v0.25.35 — Sheliak · GEN RF1/Alt memory, RPT band-change drop

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.34. Build date **2026-11-02**.

**Scope:** two tester-reported fixes on top of the v0.25.34 IO-board
sequencer. No change to the sequencer itself, to what goes on the I2C
wire, or to any DSP. Protocol 2 (Brick / ANAN) is unaffected by the GEN
RF1 / Alt change (Protocol 2 has no RF1 / Alt chip); the RPT change
applies to both protocols.

## Summary

- **GEN1 / GEN2 / GEN3 remember RF1 / Alt and LNA per slot** (GitHub
  #24, Mike K7MDL). Until now a GEN button only recalled frequency +
  mode; RF1 / Alt and the LNA stayed at whatever the previous band
  left. Each GEN slot now keeps its own **RF1 / Alt**, **LNA** and
  **Auto-LNA**, the same way the Xvtr chips do. Upgrade-neutral:
  RF1 / Alt defaults to **RF1**; LNA / Auto are remembered only once
  you touch them while that slot is active. TX drive on GEN slots is
  deliberately unchanged.
- **An FM RPT offset no longer follows you to another band** (Volker
  DL1VE). With RPT armed on the 2 m transverter, hopping to an HF band
  dragged VFO B along (RX1 − offset), left **SPLIT** lit, and sent an
  out-of-band TX frequency (e.g. 20.492 MHz) to the IO board / amp —
  and because split + VFO B persist, it survived restarts. Now, when
  RX1 crosses into a different band while RPT is active, RPT / SPLIT
  turn off, VFO B is re-synced to the new RX1, the status bar shows
  **RPT off — left ‹band›**, and the log records it.
- **Operator SPLIT is unchanged.** A split you set with the **SPLIT**
  button (or CAT / TCI / the desk) still persists across band changes
  with VFO B where you left it — the same default as Thetis and
  deskHPSDR. Only the RPT-armed split drops.
- New one-shot **`[iob] TX regs follow VFO B (SPLIT on): ‹hz› Hz`**
  verbose-log line whenever the IO-board TX registers are carrying
  VFO B rather than the dial; the **forced-present** status line now
  also shows TX Hz and REG 11, like the detected line. Log only — no
  wire traffic, REG 11 untouched.

## Detail — GEN slots (`5442443`)

Per-band RF1 / Alt + LNA + Auto-LNA memory lives in the band memory,
keyed by the ham / broadcast / CB band tables. The GEN defaults
(10.000 / 15.000 / 1.000 MHz) and most general-coverage frequencies fall
outside those tables, so the band memory neither saved nor applied
anything for a GEN slot and the live state simply carried over — which
is what K7MDL saw.

- Each GEN slot now stores `rxPort` (0 = RF1, 2 = Alt), `lnaDb` and
  `autoLna` (QSettings `gen/<n>/rxPort`, `gen/<n>/lnaDb`,
  `gen/<n>/autoLna`). Live changes while that slot is active are noted
  and persisted; recall applies them after the frequency + mode writes,
  so the slot's values win over anything the band memory pushed in
  response to the frequency write.
- Unset LNA / Auto leave the live state alone (no Xvtr-style "force
  Auto off"); unset RF1 / Alt = RF1. **Right-click → reset** clears all
  three.
- REG 11 on the wire is unchanged (still only 0 or 2).
- TX drive / TUN drive on GEN slots: intentionally not touched.

## Detail — RPT drop on band change (`b2820cd`)

RPT is implemented as SPLIT with VFO B = RX1 ± offset, and the duplex
tracker re-derived VFO B on every RX1 change while in FM with split on
— including across the band edge. The band change itself restores mode
/ LNA / drive but never touched split or VFO B, and nothing told RPT
split apart from operator split. Reference behaviour: Thetis keeps the
repeater offset per TX band and gates it on FM; deskHPSDR turns split
off and copies A → B on a band change. Neither carries a repeater
offset across bands as split.

- New `rptActive` state (persisted `tx/rptActive`): set when the
  **RPT** button or a repeater memory arms the split; cleared whenever
  split goes off (SPLIT / RPT off, A / B pip, memory recall, CAT / TCI,
  desk, the drop below) and by **1→2 / 2→1 / ⇄**.
- When RX1 crosses into a different band identity (an Xvtr slot or a
  ham / BC / CB table entry — the same identity the band memory fires
  on) while RPT is active: split off, VFO B ← RX1, status bar
  **RPT off — left ‹band›**, log
  `[hl2-safety] TX: RPT off — RX1 left ‹band› on a band change; SPLIT
  off, VFO B -> ‹hz› Hz (was ‹hz› Hz)`. Runs before the NCO pushes, so
  the tune produces one TX write and one IO-board word. Tuning inside
  one band never fires it.
- While keyed, RPT split now gets the same band-jump refusal as
  simplex (the TX would move with the drop).
- The Tuning panel duplex tracker is additionally gated on `rptActive`
  and same-band-before-and-after (belt and braces; the drop above
  fires first).
- `[iob]` diagnostic: one-shot `TX regs follow VFO B (SPLIT on): ‹hz› Hz`
  when split is on and the published TX word differs from RX1; re-arms
  when the condition clears, never per cycle. Forced-present line gains
  `TX ‹hz› Hz, REG11 ‹0 (RF1) | 2 (Alt RX)›`.
- No Settings option; the drop is unconditional for RPT only. The
  IO-board sequencer and frame composer are untouched.

**Upgrade note.** A split persisted by an older RPT session has no
`tx/rptActive` key and is **not** inferred — it loads as operator split
and behaves that way until you click **SPLIT** (or **RPT**) off once.

## Bench

Both changes are host-side state / persistence only — nothing new goes
on the I2C wire and REG 11 still only encodes 0 / 2. What to check on a
station with an IO board: **GEN** — 20 m on RF1 → GEN1, click Alt →
20 m → GEN1 should come back on Alt; GEN2 keeps its own choice; LNA per
slot; all of it after a restart. **RPT** — arm RPT on the 2 m chip, hop
to an HF band: SPLIT goes out, VFO B sits on the new band, status bar
says **RPT off — left ‹the 2 m chip's name›**, the IO-board TX word is
the HF dial. Operator
SPLIT set with the SPLIT button must still persist across the same hop.
Confirmation requested from the reporting testers, Mike K7MDL and
Volker DL1VE.
