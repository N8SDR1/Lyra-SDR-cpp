# Lyra v0.25.36 — Sheliak · Eight Xvtr slots, SWL J16 rows, digital-mode ALC

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.35. Build date **2026-11-04**.

**Scope:** the two items left queued at v0.25.35 — **eight transverter
slots** and **OC Control rows for the shortwave broadcast (SWL) bands**
— plus a transmit fix for **digital modes**: in **DIGU / DIGL** the ALC
is held to a peak limiter and the Leveler is held off, so variable-
envelope digital waveforms (RADE digital voice, PSK, OFDM) go out
unshaped. One dead Settings control (TCI **TX-in gain**) is retired. No
change to what goes on the I2C wire for the IO board (0x1D), to the
HL2 filter-board I2C traffic (0x20) on the ham bands, or to any receive
DSP. Protocol 2 radios get the eight Xvtr chips and the DIGU / DIGL
change; the SWL rows reach a Brick / ANAN only when OC is enabled for
that rig (default Off outside the HL2).

## Summary

- **Eight transverter slots** (was four), asked for by Mike K7MDL, who
  runs a five-band 2 m / 1.25 m / 70 cm / 33 cm / 23 cm stack. Slots
  5–8 start **disabled and empty**, exactly how the spare fourth slot
  has always shipped, so nothing changes on a station that uses one to
  four. One row of eight chips on an HL2; on a Protocol 2 / Alex rig
  that shares the row with the ANT / RX chips they wrap 2 × 4 so the
  Band dock keeps its width. Your existing slots 1–4 are read
  unchanged. Every place that iterates the slots — the Filters / BCD
  Xvtr OC rows, Clear all, the live-row highlight, GEN slots — follows
  the new count.
- **SWL broadcast rows on J16** (also K7MDL). A shortwave broadcast
  band used to resolve to "no row" = every J16 pin off, so an N2ADR
  board sat unfiltered on 49 m / 31 m / 19 m. Settings → **Filters /
  BCD** now has a collapsible **SWL broadcast rows** section under the
  ham and Xvtr rows, one row per broadcast band (**120 m … 13 m**,
  twelve rows), with the same RX / TX pin ticks. Precedence is **Xvtr
  slot → ham band → broadcast band → none**: where a broadcast band
  overlaps a ham band the ham row wins (7.200–7.300 is **40 m**, not
  41 m; 75 m BC sits inside 80 m so its row never fires). **CB and
  GEN1–3 still get no row** (pins off) — deliberate. The **Live J16**
  readout says `‹band› BC (SWL row)` or `none (GEN / CB / out of
  table)`.
- **SWL rows are seeded only when you ask.** Picking **N2ADR** in the
  OC accessory combo or pressing **Reload N2ADR HF** fills the twelve
  rows with the RX LPF of the ham band just above each one, **TX
  unticked** (RX-only filters — a seeded TX mask would pull an LPF
  relay on key at a broadcast frequency). First run, a rig switch and
  the default N2ADR stamp for a new rig stay **ham-only**; until you
  reload, the SWL rows are empty (pins off) — the same as before this
  build. Log line: `[oc] SWL rows seeded from N2ADR (12 rows, TX off)`.
- **Digital modes: ALC is a limiter only, Leveler held off.** In
  **DIGU / DIGL** the ALC max gain is capped at **1.0**, so it only
  catches peaks over full scale, and the **Leveler** is held **off**
  regardless of the toggle. Voice modes keep your ALC / Leveler
  settings; nothing saved changes. Found while testing **RADE** digital
  voice through **STD** over TCI — the ALC's 3.0 max gain with its 10 ms
  decay was riding the gain of variable-envelope waveforms so others
  could not decode them, while constant-envelope FT8 got through.
  Confirmed on the air (first RADE contact) 2026-11-04. Applies to any
  TCI or VAC client keying DIGU / DIGL (MSHV, WSJT-X, JTDX, VarAC, STD,
  Open SSTV …) — you no longer need to turn the Leveler off by hand for
  digital.
- **TCI TX-in gain control removed.** Settings → **Network** → TCI
  **TX-in gain** had been a no-op since June; the level of the TX audio
  Lyra receives from a TCI client is set by the client app's own drive,
  Lyra's **digital drive %**, and the ALC. The saved `tci/tx_gain_db`
  key is ignored. **RX-out gain** stays.

## Detail — eight transverter slots (`546813d`)

One shared count now drives everything that iterates the Xvtr slots:
the Band-dock chips, the per-slot saved state, the Filters / BCD Xvtr
OC rows and their saved pin masks. They cannot drift apart.

- `lyra::xvtr::kSlotCount = 8` (`src/xvtr_math.h`) is the single
  source; `XvtrSlots::kCount` and `OcControl::kXvtrSlots` alias it.
- Slots 5–8 default **disabled**, named by number — the untouched state
  slot 4 has always shipped in. Existing `xvtr/0..3` data is read
  unchanged; `xvtr/4..7/...` keys are additive.
- Band dock: the Repeater model is `Xvtr.slotCount`. One row of eight
  on an HL2 (fits the default dock width like the Ham row). When the
  Alex ANT / RX chips share the row (Protocol 2 / desk ladder) the chips
  wrap 2 × 4 so the dock minimum width stays what it is today.
- OC grid rows, save / load loops, Clear all, live-row highlight,
  `bandIdFor xvtr:N` and GEN slots already iterated the constant and
  needed no change.
- Tests: 8 Xvtr OC rows, last row addressable, a ninth rejected;
  `kSlotCount == 8`.

## Detail — SWL broadcast rows on J16 (`ecb041c`)

Broadcast (SWL) bands resolved to index −1 = all J16 pins off. CB
(11 m) and GEN1–3 deliberately keep that behaviour.

- **Row index space.** Rows 0–10 are the amateur bands (unchanged);
  rows 11–22 are the twelve broadcast bands (120 m, 90 m, 75 m, 60 m,
  49 m, 41 m, 31 m, 25 m, 22 m, 19 m, 16 m, 13 m). Mask setters and
  getters take a row; existing amateur callers are untouched.
- **`rowForHz(hz, xvtrSlot)`:** Xvtr slot → amateur → broadcast → none.
  Ham wins every overlap (75 m BC inside 80 m; 41 m BC 7.2–7.3 vs 40 m;
  13 m BC 21.45 vs 15 m) — zero change to behaviour on the ham bands.
- **Pin-table group.** Amateur rows use group 0; broadcast rows use
  group 2 (the SWL pin-action / external-PA set that was already
  persisted); anything else −1.
- **HL2 RX2 "higher band" pick** now compares band frequency, not row
  number, since the broadcast rows follow the ham rows in the index.
- **Stream:** the OC band lookup goes through `rowForHz(ddsHz,
  xvtrSlot)`.
- **Persistence** (additive, per rig): `swlRxA/N`, `swlTxA/N`,
  `swlRxB/N`, `swlTxB/N`, N = broadcast-band index. Rigs saved before
  these keys existed read 0 = pins off until you reload.
- **Settings → Filters / BCD:** the SWL rows live in the same grid
  under a fold-arrow header **SWL broadcast rows (12) — ham row wins on
  overlap**, folded by default; open state in `hw/ocSwlRowsOpen`. The
  live-row highlight covers them; the status reads **Live J16: 49m BC
  (SWL row)** or **none (GEN / CB / out of table)**. Help text and
  tooltips mention the seeding and the ham-wins rule.

## Detail — SWL second pass: operator-only seed, RX-only, straddles (`ec07dab`)

Design-review follow-up to the rows above.

1. **No automatic SWL seeding.** The stock N2ADR stamp that runs for
   every new rig bucket (first run, each rig switch) is back to **ham
   rows only**. A separate SWL seed runs **only** from the OC accessory
   combo when you pick **N2ADR**, and from the **Reload N2ADR HF**
   button (both route to the same place). Missing `swl*` keys load as
   literal 0. Log: `[oc] SWL rows seeded from N2ADR (12 rows, TX off)`.
2. **RX-only masks.** The SWL TX seed is 0 for every band — no
   out-of-ham TX block; a seeded TX mask would pull an LPF relay on key
   at a broadcast frequency. Hand-ticking a TX pin still works.
3. **Straddle picks.** 41 m borrows the **40 m** row (RX pins 3 + 7)
   and 13 m borrows the **15 m** row (RX pins 5 + 7) — identical to the
   adjacent ham row, so the change gate stays silent across 7.300 /
   21.450. 120 m drops the 3 MHz HPF (pin 2 only).
4. **Bounds.** Every mask getter / setter and the compute path use the
   full row count; the group split is ham / SWL / −1; pin tables are
   indexed by group only. Stream and Settings loops audited.
5. **Protocol 2 note:** SWL rows reach Brick3 `[1401]` only when OC is
   enabled for that rig (default Off for non-HL2).

**Seed table (RX pins; TX always off):**

| BC band | RX pins | Borrows |
|---|---|---|
| 120 m | 2 | 80 m LPF, no 3 MHz HPF (below 3 MHz) |
| 90 m | 2, 7 | 80 m |
| 75 m | 2, 7 | 80 m (row never fires — inside 80 m) |
| 60 m | 3, 7 | 60 / 40 m |
| 49 m | 3, 7 | 60 / 40 m |
| 41 m | 3, 7 | 40 m (straddle pick) |
| 31 m | 4, 7 | 30 / 20 m |
| 25 m | 4, 7 | 30 / 20 m |
| 22 m | 4, 7 | 30 / 20 m |
| 19 m | 5, 7 | 17 / 15 m |
| 16 m | 5, 7 | 17 / 15 m |
| 13 m | 5, 7 | 15 m (straddle pick) |

Tests: 22 groups — ham-only stamp leaves every SWL row 0; a 1 kHz dial
sweep 0–60 MHz never returns a row a getter rejects and broadcast rows
never alias ham rows; band-name consistency over every ham / BC / CB
edge ±1 Hz plus 7.200 / 7.300 / 7.301 / 21.450 / 21.451 / 3.900. A
static source check ensures exactly one SWL seed call exists and it is
in the accessory setter.

## Detail — ALC limiter + Leveler off in DIGU / DIGL (`f9042df`)

The ALC's 3.0 max gain rode the gain of any signal peaking above about
0.33 full scale, with a 10 ms decay. That reshaped variable-envelope
digital waveforms such as RADE / OFDM digital voice and PSK, so others
could not decode them, while constant-envelope FT8 got through. The
Leveler was parked only for a DeskLink digital key and browser voice; a
local TCI or VAC client keying in DIGU / DIGL got the operator's Leveler
and the full ALC gain.

- New digital TX-levels step, applied on every mode change, on channel
  open, from the ALC and Leveler setters and from the Leveler push.
- In **DIGU / DIGL**: ALC max gain capped at **1.0** (limits peaks over
  full scale only); **Leveler off**, and it also honours the existing
  Leveler hold-off.
- Voice modes keep the operator values. Saved settings are unchanged —
  switch back to USB and your ALC / Leveler are as you left them.
- Found while testing RADE digital voice through STD over TCI;
  confirmed on the air (first RADE contact) 2026-11-04.

## Detail — TCI TX-in gain control retired (`2b04d57`)

The Settings → Network → TCI **TX-in gain** spinner had been a no-op
since the June TX refactor: the per-sample multiply was dropped and
never restored, so the control only updated a cached value nothing
read. Digital-mode TX over TCI (MSHV, STD, VarAC, Open SSTV, WSJT-X,
JTDX) has worked without it the whole time.

- Spinner, label, tooltip and preference wiring removed; the **RX-out
  gain** row stays.
- Saved `tci/tx_gain_db` key is left as a harmless orphan (no
  migration, no delete). An older saved profile carrying the field is
  ignored on load.
- Inbound TCI TX audio is decode → resample → push; the level is set by
  the client app's own TX / drive slider, Lyra's **digital drive %**,
  and the ALC (a peak limiter only in DIGU / DIGL, above).
- User Guide and the CW / TX design note no longer describe the
  control.

## Bench

Nothing new goes to the IO board (0x1D); the J16 / 0x20 pattern on the
ham bands is unchanged. What to check on an HL2 with an N2ADR board:

- **Reload N2ADR HF** (Settings → Filters / BCD) → open the **SWL
  broadcast rows** fold → twelve rows populated with RX ticks, **TX
  unticked** on every row; log shows `[oc] SWL rows seeded from N2ADR
  (12 rows, TX off)`.
- Dial **5.975 MHz** → Live pins 3 + 7, status **Live J16: 49m BC (SWL
  row)**. **7.200** → **40m** (ham wins). **7.350** → **41m BC (SWL
  row)**, same pins 3 + 7 (no relay click across 7.300). **21.460** →
  13m BC, pins 5 + 7. **2.400** (120 m) → pin 2 only.
- A **CB** channel or **GEN1** → **none (GEN / CB / out of table)**,
  all pins off.
- Before pressing Reload on a fresh install / new rig, the SWL rows are
  empty and a broadcast frequency gives all pins off, as in v0.25.35.
- **Xvtr row:** eight chips on the Band dock; slots 5–8 disabled until
  you right-click and enable them; chips 1–4 come back with their old
  names / RF / LO; dock width unchanged. Restart — all eight persist.
- **DIGU** with a digital app (STD / MSHV / WSJT-X over TCI or VAC):
  ALC meter sits near **0 dB** on a steady tone, the Leveler indicator
  is **off** even if the Leveler toggle is on. Switch to **USB** voice:
  ALC / Leveler behave as before with your saved values.
- Settings → Network → TCI: **TX-in gain** is gone; **RX-out gain** is
  there.
