# Lyra v0.25.46 — Jugum · TCI start, crash fixes, wheel settings

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Jugum** (δ Lyrae).
Patch over v0.25.45. Build date **2026-11-25**.

Installer app identity stays **Lyra-cpp** (same QSettings as 0.25.45).
Install over 0.25.45; settings stay.

## Summary

- **SDRLogger+ no longer stops the radio.** A TCI client that sends
  `start;` when it connects (SDRLogger+ does) stopped a running
  **Protocol 2** radio (Brick, ANAN), and you had to press Start again.
  A TCI or CAT start now only starts a radio that is stopped, on either
  protocol. A CAT stop now also works on Protocol 2.
- **Startup crash fixed.** With a TX/RX profile that sets VAC buffer size
  or latency (a VarAC-style profile, for example), Lyra could close a few
  times before it opened.
- **Crash on exit fixed.** Lyra could crash as it closed (nothing was
  lost; Windows logged it).
- **Mouse wheel / USB tuning knob settings.** Settings → Hardware
  **Navigation** is now **Mouse wheel** and **USB tuning knob
  (optional)**, with plain names and a warning not to pick your everyday
  mouse as the knob — doing that made the mouse wheel seem to stop
  working. Behaviour is unchanged.
- **Unchanged:** wheel after a drop-down (0.25.45). QRV board and
  double-click tune (0.25.43–44). WDSP 2.11 + CW NNR models (0.25.42).
  ASIO for VAC in test (0.25.41).

## What testers should try

- Protocol 2 radio running, then open SDRLogger+ (or another TCI client):
  Lyra keeps running.
- Start Lyra a few times with your usual default profile: it opens first
  time.
- Settings → Hardware: check the **Mouse wheel** and **USB tuning knob**
  groups read clearly. If you don't have a USB tuning knob, leave that
  group off.
