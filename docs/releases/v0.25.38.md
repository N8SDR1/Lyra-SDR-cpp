# Lyra v0.25.38 — Sheliak · DeepFist pitch lock

Hermes Lite 2 / 2+ (Protocol 1) and **BrickSDR2 / Brick3SDR** (Protocol 2).
Windows 10 / 11.

This is a **full** GitHub release so the in-app updater and
`/releases/latest` both see it. Star name stays **Sheliak**. Patch over
v0.25.37. Build date **2026-11-07**.

**Scope:** DeepFist (neural CW decoder) now locks to the operator **CW
pitch** (±80 Hz) and commits a character sooner. **Classic** (fldigi)
is unchanged. Original decoder: **Brent Crier (N9BC)**. No Protocol 2
or HL2 wire change. 7000DLE / 8000DLE TX, Xvtr BYTE0–4, and Metis STOP
from v0.25.37 stay.

## Summary

- **DeepFist locks to your CW pitch.** The neural decoder searches
  only within ±80 Hz of the operator CW Pitch. A louder station nearby
  is no longer copied instead.
- **Earlier character commit.** A letter prints once two consecutive
  decodes agree on it, still capped at the old 1.3 s delay.
- **Classic unchanged.** The fldigi engine on the **Classic** chip is
  the same as v0.25.37.
- **Unchanged:** G2 / G2-1K still need the dummy-load arm. Red Pitaya
  has no P2 TX profile. Protocol 1 ANAN is still refused. HL2 / Brick /
  10 / 100-series / 7000 / 8000 TX posture is otherwise unchanged.

## Detail — DeepFist (`e7c465a`, cherry-pick of `edd19a1`)

Tone search is limited to ±80 Hz of the radio's CW Pitch (the same
tone Classic listens at). A 150 Hz clean-up mask follows the
conditioner. The keying gate is 6 (was 12) so weak and fading signals
still print without filling the pane on noise. Characters commit when
two consecutive rolling-window decodes agree, never stalling past the
old guard delay.

Confirmed on air by N8SDR. Offline bench
(`scratch/test_cw_neural_bench.cpp`, synthetic CW): mean character
error 40% → 3.5%, average display delay 1.4 s → 1.0 s.
